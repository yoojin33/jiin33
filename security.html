Web Hacking & Vulnerabilities

대표적인 웹 공격 기법의 원리를 파악하고 위협에 대비하세요.

High Risk

1. SQL Injection

데이터베이스 쿼리에 악성 SQL 문을 넣어 로그인 우회, 정보 탈취, 데이터 변조를 일으키는 공격입니다.

공격 원리 예시

로그인 폼에 아래와 같은 구문을 입력하면 쿼리가 항상 '참'이 됩니다.

<form method="post" action="/login">
<input name="id">
<input name="pw" type="password">
<button type="submit">Login</button>
</form>

<script>
const query = "SELECT * FROM users WHERE id = '" + id + "' AND pw = '" + pw + "'";
</script>
High Risk

2. XSS (Cross-Site Scripting)

웹페이지에 악성 스크립트를 삽입해, 사용자의 브라우저에서 쿠키 탈취, 세션 악용, 화면 조작을 일으키는 공격입니다.

<div id="comment"> </div>

<script>
const comment = userInput;
document.getElementById("comment").innerHTML = comment;
</script>
High Risk

3. CSRF (Cross-Site Request Forgery)

사용자가 의도하지 않은 요청을 보내게 만들어, 로그인된 상태를 악용하는 공격입니다.
사용자가 모르는 사이에 계정 설정이 바뀌거나 송금이 실행될 수 있습니다.

공격 원리 예시

사용자의 브라우저가 의도하지 않은 요청을 보내면 CSRF가 발생할 수 있습니다. 실제 서비스에서는 CSRF 토큰 검증과 같은 방어가 필요합니다.

<img src="https://example.com/account/change-email?email=attacker@example.com" style="display:none;"> >
High Risk

4. 업로드 취약점

파일 업로드 기능의 허점을 이용해 악성 파일을 올리는 공격입니다.
웹셸이나 실행 파일이 업로드되면 서버가 위험해질 수 있습니다.

공격 원리 예시

파일 확장자 검사만 믿거나 업로드 파일을 그대로 실행하면 위험해질 수 있습니다.
안전한 서버는 허용 형식 제한, 저장 경로 분리, 실행 권한 차단이 필요합니다.

<form action="/upload" method="post" enctype="multipart/form-data">
<input type="file" name="file">
<button type="submit">Upload</button>
</form>
Medium Risk

5. 디렉터리

허용되지 않은 폴더나 파일 경로에 접근하는 취약점입니다.

공격 원리 예시

입력값을 그대로 경로에 붙이면 원치 않는 파일 접근이 생길 수 있습니다.
경로 검증과 허용 목록 방식이 필요합니다.

const path = "/var/www/uploads/" + req.query.file;
res.sendFile(path);
High Risk

6. 인증 우회

정상적인 로그인 절차를 건너뛰고 접근 권한을 얻는 공격입니다.
비밀번호 없이 관리자 페이지에 들어가는 경우가 있습니다.

공격 원리 예시

인증 절차를 건너뛰게 만들 수 있습니다.
서버에서는 로그인 검증, 세션 확인, 권한 검사를 분리해서 처리해야 합니다.

if (req.body.username === "admin") {
res.redirect("/admin");
}
High Risk

7. 하이재킹

정상 세션이나 접속 정보를 가로채서 탈취하는 공격입니다.

공격 원리 예시

세션 토큰이 노출되면 다른 사용자인 척 접속할 수 있습니다.
세션 보호, HTTPS, 만료 시간, 재발급이 중요합니다.

fetch("/mypage", {
headers: { "Cookie": "session=stolen-session-id" }
});
